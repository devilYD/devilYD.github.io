# Rayburst：一个现代开源下载器该有的样子

浏览器自带的下载器，下几张小图、几个安装包还算顺手；一旦遇到几十 GB 的系统镜像、整季的课程视频，或者一串磁力链接，就很容易暴露短板：不能多线程、断点续传看运气、任务一多就乱成一团。

IDM 是很多人的第一选择，速度快、接管浏览器也成熟，但它收费，而且只支持 Windows。迅雷的生态和离线加速确实强，代价是广告、限速和一堆用不上的功能。再往下就是 aria2：内核强大、协议齐全、资源占用低，但命令行和配置文件把大部分普通用户挡在了门外。

所以我一直在找一种组合：**aria2 的内核、现代的图形界面、跨平台、开源无广告**。最近在 GitHub 上看到的 Rayburst，是目前最接近这个描述的项目之一。

## 先说结论

如果你想要一个 IDM 的跨平台替代品，或者早就听说过 aria2 但不想折腾命令行，Rayburst 值得放进候选名单。

它的长处是协议覆盖非常全，界面和交互跟得上现在的桌面应用，MIT 开源、没有广告；短板也很明确：暂不提供便携版，代码签名不完整，从 Motrix Next 更名而来，生态还很年轻。

## Rayburst 是什么

Rayburst 是一个开源的跨平台下载管理器，前身是 Motrix Next。官方在 README 里已经说明这次更名，并建议先卸载旧版再安装。

它没有自己从头写下载内核，而是使用了 [Aria2 Next](https://github.com/AnInsomniacy/aria2-next)——一个持续维护的 aria2 分支，保留了原来的接口，同时补上了 ED2K、HLS/DASH 等能力。Rayburst 负责的是界面、任务管理、浏览器接管和系统集成，相当于给 aria2 配了一个现代的外壳。

项目在 2026 年 3 月创建，到写这篇文章时已经有 1.1 万+ Star。版本迭代很快，v4.1.1 主要修了重试后文件损坏、Windows 安装器、慢速 IPv6 路由等问题，同时把 Aria2 Next 升到了 3.0.9。

## 它到底能下什么

这是 Rayburst 最值得说的地方。很多“下载器”只支持 HTTP，BT 是附赠的，流媒体基本不管；Rayburst 的协议覆盖要完整得多：

- **HTTP / HTTPS / SFTP**：常规直链、网盘直链、服务器文件；
- **BitTorrent / Magnet / `.torrent`**：支持选择文件、DHT、PEX、加密、元数据缓存、GeoIP 节点标记和 Tracker 探测；
- **ED2K**：通过 Aria2 Next 原生支持；
- **HLS / DASH**：可以选择音视频轨道和字幕，支持直播录制、断点续传，输出 MP4/MKV。

也就是说，日常的安装包、镜像、课程视频、磁力资源，基本可以放在一个应用里管理，不用在几个工具之间来回切换。

BT 这部分并不是“能连上就行”。选择性下载、DHT、PEX、加密策略、Tracker 探测这些都有对应的图形化选项，对经常下 BT 资源的人来说，比很多套壳客户端要实用。

HLS/DASH 则是另一个差异点。很多课程网站和流媒体站点把视频切成大量小分片，普通下载器只能一集一集地抓，Rayburst 可以直接把整个流当成一个任务处理，还能保留字幕和音轨。当然，它不负责绕过 DRM，能下什么取决于资源本身；请只下载自己有权获取的内容。

界面部分，它提供浅色、深色、跟随系统三种主题，10 套配色，27 种语言，首次启动会按系统语言自动选择。官方说动效遵循 Material Design 3 的节奏，这部分见仁见智，但至少不是那种“功能能用、界面停留在十年前”的开源工具。

## 浏览器接管与日常使用

Rayburst 配套了一个浏览器扩展 [Rayburst Connect](https://github.com/AnInsomniacy/rayburst-connect)，通过 Native Messaging 和桌面端通信。装好之后，浏览器里的下载可以交给 Rayburst：支持下载确认、智能自动提交、文件名提示、Referer/Cookie 转发，以及任务开始后的实时控制。

这对经常从网页直接拖文件的人很关键——不用复制链接再切回客户端，体验接近 IDM 的浏览器接管。

任务管理方面，它提供了收藏/最近文件夹、按文件类型自动分类、失效记录清理，完成历史存在 SQLite 里；活动任务数、连接数、BT Peer 数可以分别限制。限速支持全局和单任务，还能按星期几、时间段排程——比如白天限速、凌晨全速。

系统集成也做得比较全：托盘常驻、托盘显示速度、macOS Dock 进度、任务完成通知、下载时阻止休眠、完成后自动关机，以及 `magnet://`、`ed2k://`、`thunder://`、`rayburst://` 协议处理器。复制一个磁力链接直接唤起客户端，算是下载器的基本功了。

还有一个我比较喜欢的设计：**轻量模式**。最小化到托盘后，它会销毁包括悬浮球在内的所有 WebView，只保留 Rust 后端继续跑下载引擎、任务监控、通知和历史。对内存紧张的笔记本来说，这比“最小化后还挂着一个 Chromium”要友好得多。

## 安装

所有安装包都在 [GitHub Releases](https://github.com/AnInsomniacy/rayburst/releases) 发布，按系统和架构选择：

| 平台 | 架构 | 文件 |
| --- | --- | --- |
| Windows | x64 | `Rayburst_4.1.1_x64-setup.exe` |
| Windows | ARM64 | `Rayburst_4.1.1_arm64-setup.exe` |
| macOS | Apple Silicon | `Rayburst_4.1.1_aarch64.dmg` |
| macOS | Intel | `Rayburst_4.1.1_x64.dmg` |
| Linux | x64 / ARM64 | `.deb`、`.rpm`、`.AppImage` |

Windows 双击安装即可，官方说大约 10 秒、不需要重启；以 v4.1.1 的 x64 安装包为例，体积约 25 MB，在桌面下载器里算比较克制的。Linux 的常用命令：

```bash
# Debian / Ubuntu
sudo dpkg -i Rayburst_4.1.1_amd64.deb

# Fedora / RHEL
sudo rpm -i Rayburst-4.1.1-1.x86_64.rpm

# 其他发行版
chmod +x Rayburst_4.1.1_amd64.AppImage
./Rayburst_4.1.1_amd64.AppImage
```

Flatpak 也有社区维护的包（x64），不过应用内更新器管不到它，需要用 `flatpak update` 单独更新。

### 两个安装前的提醒

第一，**它没有便携版**。不是作者偷懒，而是 Tauri 的 sidecar 架构决定的：Aria2 Next 的可执行文件必须和主程序放在一起，磁力/ED2K 协议注册和自动更新也需要安装器写入系统。官方明确说这三点绕不过去，所以 Windows 端只提供 NSIS 安装包。

第二，**代码签名不完整**。macOS 构建只做了 ad-hoc 签名、没有公证；Windows 的 Authenticode 签名是可选的，未签名安装包可能触发 SmartScreen。如果你遇到 macOS 提示“应用已损坏，无法打开”，官方给的处理是：

```bash
xattr -dr com.apple.quarantine /Applications/Rayburst.app
```

这条命令只是去掉 Gatekeeper 的隔离属性，**前提是你确认安装包来自官方 Releases**。不要对来源不明的应用执行类似操作。

## 从 Motrix Next 升级要注意

如果你之前用过 Motrix Next，官方明确说明：**设置、任务和历史记录不会导入**，下载好的文件不受影响。建议先卸载旧版，再安装 Rayburst；否则应用内更新可能让两个版本同时存在，或者留下旧快捷方式。

如果你是新用户，这一段可以跳过。

## 适合谁，不适合谁

**推荐给：**

- 经常下载大文件、系统镜像、数据集，需要多线程和断点续传的人；
- 有 BT/磁力需求，想要一个图形化客户端而不是命令行 aria2 的人；
- 需要下载 HLS/DASH 课程视频，并且想保留字幕/音轨的人；
- 用 Windows + macOS + Linux 多台设备，希望界面和配置习惯统一的人；
- 在意开源、无广告、可自己编译的人。

**可能不适合：**

- 必须用便携版、把软件放 U 盘里到处跑的人；
- 只从应用商店安装软件、不接受 SmartScreen 警告的人；
- 只下几 MB 的小文件，浏览器自带下载器就够用的人；
- 依赖迅雷离线空间、网盘加速等专有服务的人——Rayburst 替代不了这些生态。

## 几个使用建议

1. **先装浏览器扩展**。不装 Rayburst Connect，它就只是一个独立的下载器；装了之后才是完整的“接管浏览器下载”体验。
2. **连接数不要无脑拉满**。多连接对部分服务器反而会触发 403 或限速；v4.1.1 已经会在服务器拒绝额外连接时自动降低连接数，但初始值还是按自己的网络情况调。
3. **BT 任务打开 DHT 和加密**。这两个选项能明显改善连通性，尤其是在没有公网 IP 的环境里。
4. **用限速排程代替手动切换**。白天限速保证正常上网，凌晨放开跑大文件，配合“完成后关机”很适合挂机下载。
5. **代理按作用域配置**。它支持分别给下载、应用更新、Tracker 更新设置代理，不需要让整个应用都走同一条线路。
6. **更新通道选稳定版**。除非你想尝鲜，否则没必要追 Beta 或 Latest。

## 最后

下载器是一个很成熟的品类，但“开源、跨平台、协议全、界面不凑合”这几个条件同时满足的选择并不多。Rayburst 的思路很务实：不重复造下载内核，把 aria2 的能力包装成普通人能用的样子，再把浏览器接管、托盘、限速、HLS 这些细节补齐。

它还不够完美：没有便携版、签名不完整、更名后生态仍在重建，项目也很年轻。但如果你愿意接受这些前提，它值得作为主力下载器的候选。

我接下来会使用它一段时间，之后再补一篇关于实际速度、资源占用和稳定性表现的体验。项目是 MIT 开源的，本文没有利益相关，觉得有用的话可以去 GitHub 点个 Star。
